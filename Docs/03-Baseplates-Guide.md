# Baseplates Guide (Project Starter Engine)

A **Baseplate** is a foundational, production-ready project starter template provided by **SwiftBlock**. When you initialize a baseplate using `swiftblock baseplate <Name>`, SwiftBlock sets up complete multi-target architecture, build manifests (**Tuist** or **XcodeGen**), linting guardrails, and automated setup scripts.

---

## 1. Available Baseplates

SwiftBlock ships with two primary baseplate starter engines:

| Baseplate | Target Platform | Description |
|---|---|---|
| **`SwiftUI`** | iOS 15.0+ / macOS 12.0+ | Modular SwiftUI application with Tuist or XcodeGen multi-target architecture. |
| **`Vapor`** | macOS / Linux (Server) | High-performance Swift backend web API service powered by Vapor. |

---

## 2. Initializing a Baseplate (`swiftblock baseplate`)

### Basic Command

```bash
swiftblock baseplate MyApp --bundle-prefix com.mycompany --baseplate vapor
```

### Selecting Build System Tool (`--tool`)

SwiftBlock supports two industry-standard Swift build manifest generators for SwiftUI baseplates:

#### Option A: Tuist (Default & Recommended)

Generates pure Swift build manifests (`Project.swift` and `Tuist/`):

```bash
swiftblock baseplate MyApp --tool tuist
```

#### Option B: XcodeGen

Generates YAML-based build manifests (`project.yml`):

```bash
swiftblock baseplate MyApp --tool xcodegen
```

## 3. Baseplate Anatomy & Multi-Target Architecture

Every `SwiftUI` baseplate generated by SwiftBlock features a clean, modular multi-target directory structure:

```
MyApp/
├── App/
│   ├── Sources/
│   │   ├── App/                   # App Entry Point & Navigation Coordinator
│   │   │   ├── MyApp.swift
│   │   │   └── AppCoordinator.swift
│   │   ├── Core/                  # Shared Infrastructure & Services
│   │   │   └── DependencyContainer.swift
│   │   └── Features/              # Modular Feature View & ViewModel Layers
│   └── Tests/                     # Swift Testing Unit & UI Test Suites
├── Project.swift                  # Tuist Project Manifest (or project.yml)
├── Makefile                       # Developer automation scripts (make setup, make generate)
├── .swiftblock/
│   └── config.yml                 # SwiftBlock project configuration
├── .swiftlint.yml                 # Pre-configured SwiftLint rules
├── .swiftformat                   # Pre-configured SwiftFormat rules
└── Scripts/                       # Build phase & CI/CD scripts
```

## 4. Pre-Configured Developer Tooling & Guardrails

Every Baseplate includes production-ready developer automation out of the box:

### A. Automation Makefile (`make`)

```bash
cd MyApp

# Install local tools, git pre-commit hooks, and generate Xcode workspace
make setup

# Regenerate Xcode workspace after adding files or targets
make generate

# Run full unit test suite
make test

# Run SwiftLint & SwiftFormat code formatters
make format
```

### B. Code Quality Guardrails
- **SwiftLint**: `.swiftlint.yml` pre-configured with Apple & Swift style guidelines.
- **SwiftFormat**: `.swiftformat` rules enforced on save and pre-commit.
- **Git Hooks**: Pre-commit hooks automatically check linting and test compilation before commits.

## 5. Dry-Run Simulation

You can simulate baseplate initialization without writing files to disk using `--dry-run`:

```bash
swiftblock baseplate MyApp --dry-run
```

Output:
```
[Dry-Run] Would create directory: ./MyApp
[Dry-Run] Would write: ./MyApp/Project.swift
[Dry-Run] Would write: ./MyApp/App/Sources/App/MyApp.swift
[Dry-Run] Would write: ./MyApp/Makefile
```
